# CMADRE v2：藻毒素风险估计模型入门

## 1. 先用一句话理解它

这个项目要做的是：

> 根据一次采样时能拿到的水质、气候和环境信息，估计当前水体中的 total microcystins（总微囊藻毒素）或 MC-LR 浓度、它的不确定范围，以及超过 1 μg/L 预警线的风险。

这里的“当前”很重要。模型目前是 **nowcast（当前状态估计）**，不是“预测三天后会有多少毒素”的时间序列预报。现有数据缺少严格滞后的连续气象、水文、遥感和毒素序列，因此不能把当前结果包装成 1/3/7 天预报。

它在整个 iGEM 系统中的位置是：

```text
水质/环境观测 ──> CMADRE v2 风险估计 ──> 预警
                         │
                         ├──> 浓度标定模块：把工程菌的光信号换成浓度
                         ├──> 二维水流模块：推演投放后菌团会漂到哪里
                         └──> 降解/路径模块：决定怎样治理、何时投放
```

## 2. 它具体解决什么问题

项目把看起来相似的目标拆成了不同任务：

| 任务 | 含义 | 当前用途 |
|---|---|---|
| total MC | 总微囊藻毒素 | 数据量较大的主训练任务 |
| MC-LR | 其中一种具体毒素构型 | 与项目传感器和治理目标直接相关 |
| 检出/阈值风险 | 是否检出、是否可能超过 1 μg/L | 为预警决策准备概率 |
| 中国/东湖域适配 | 东湖的环境特征与训练数据有多像 | 当前主要用于后续 OOD/域适配设计 |

**total MC 不等于 MC-LR。** 不同检测方法可能测的是总量、某一构型，或 ADDA-ELISA 当量；把它们直接混成一个标签，会得到看似样本很多、实际含义混乱的模型。因此 CMADRE 把两种分析物分开建模。

## 3. 为什么这个项目比普通回归麻烦

### 3.1 “没检出”不是“浓度为 0”

许多水质检测结果不是一个精确数值，而是“低于检测限 LOD”。例如实验报告写 `<0.05 μg/L`，正确的信息是：真实值落在 `[0, 0.05]`，而不是把它改成 0、LOD/2，或者直接删掉。

因此项目内部把每个标签写成区间 `[L, U]`：

- 精确测量值 `y` → `[y, y]`；
- 低于检测限 → `[0, LOD]`；
- 已知上下界 → `[L, U]`。

这种情况叫“左删失/区间删失”。`labels.py` 负责解析标签，XGBoost AFT 和删失感知 TabM 使用区间似然；普通模型只能作为对照，不能偷偷把这些信息改成一个假精确值。

### 3.2 数据来自不同国家、湖泊和检测方法

当前 total MC 表约有 2 万条记录，但约一半是删失值，主要来自美国；MC-LR 有效数据少得多，且动态数据有明显的单一来源集中。中国和东湖有大量环境协变量，却几乎没有对应的毒素标签。

所以本项目不能用随机逐行切分来制造“高分”。如果同一个来源或同一个水体同时出现在训练集和测试集，模型可能只是记住了来源特征。正式评估使用：

- source-OOD：留出整个数据来源；
- waterbody-OOD：留出整个水体；
- temporal-OOD：按时间分组留出。

每一折都检查训练、验证、测试的分组没有交集，并报告来源宏平均和最差来源表现。

## 4. 模型是怎样工作的

可以把完整流程看成六步：

```text
原始水质表
   ↓
数据契约与标签区间
   ↓
特征白名单、缺失处理、非 IID 切分
   ↓
多个“专家”分别建模
   ↓
OOF stacking + CQR 区间校准 + OOD 检测
   ↓
浓度中位数、q10–q90 区间、超阈值概率、域外标记
```

### 第一步：整理输入特征

`features.py` 负责生成预先规定的特征面板，例如现场水质、叶绿素/蓝藻指标、气候、静态环境和土地覆盖特征。特征列采用白名单，防止把标签、未来信息或来源标识意外喂给模型造成泄漏。

### 第二步：训练不同类型的专家

当前架构不是押注一个“排行榜最高”的模型，而是组合不同长处：

| 专家 | 直观理解 | 主要作用 |
|---|---|---|
| XGBoost AFT | 能直接处理 `[L,U]` 区间标签的树模型 | 删失统计核心、稳定基线 |
| CatBoost/XGBoost 分位数树 | 分别预测 q10、q50、q90 | 给出不依赖单一分布假设的区间 |
| TabM-inspired 删失小型集成 | 带缺失指示和删失似然的轻量神经网络 | 提供与树模型不同的概率专家 |
| Hurdle 检出头 | 把“是否检出”和“检出后浓度”拆开 | 已有接口，当前不是正式主力 |
| TabICLv2 | 可选的表格基础模型挑战者 | 接口已实现，尚未进入正式 v2 结论 |

### 第三步：用折外预测做集成

不能用训练集上的预测直接学集成权重，否则会泄漏。项目在每个外层训练折内部再做 OOF（out-of-fold）预测，只用这些“模型没见过的训练样本预测”学习 stacking 权重。当前尝试过非负 NNLS、分布式 stacking 和 log-blend；log-blend 的作用可以直观理解为：一个专家突然给出极端大值时，不让它单独把最终结果拉爆。

### 第四步：校准区间

模型先给出一个初始区间，再用验证集上的 Conformalized Quantile Regression（CQR）调整区间宽度，使“名义 90% 区间”尽量接近实际覆盖率。校准只使用验证集，不碰 locked test。

### 第五步：标记分布外样本

`ood.py` 用特征协方差和 Ledoit-Wolf 马氏距离计算样本与训练域的距离，超过训练域 99 分位阈值就输出 `ood_flag`。这不是说样本一定错误，而是在提醒：它和模型见过的数据很不一样，预测应降低信任，并最好安排补充采样。

### 第六步：保存可复现制品

一次完整运行会保存配置、数据摘要与哈希、分组切分清单、模型文件、校准器、预测表、指标、依赖版本和运行状态。推理时加载运行目录即可对新的 CSV/Parquet 批量预测，不必重新训练。

## 5. 输出怎样读

每个样本的主要输出包括：

- `median_ug_l`：浓度后验中位数，不应单独当成绝对真值；
- `q10/q90` 或校准后的预测区间：表达不确定性；
- `P(Y>τ)`：超过某个风险阈值的概率，阈值可以配置；
- `ood_score`、`ood_flag`：是否偏离训练域；
- 各专家预测和集成结果：用于追查模型为什么给出这个答案。

因此，预警逻辑应是“概率 + 区间 + OOD 一起看”，而不是只看一个回归数字。

## 6. 当前结果能说明什么

正式锁定测试显示：v2 相比早期版本在 total MC 和 MC-LR 任务的 log1p 误差上有所改善；MC-LR core 的排序能力也有一定增量。但局限同样明确：

- total MC 的简单 Random Forest 在同一跨来源切分上仍可能优于 v2 的点预测；
- MC-LR static 的排序很弱，行数也被同站点同日重复放大；
- total MC 约 99.5% 数据来自美国/加拿大，MC-LR 动态数据集中在少数来源；
- 训练域与中国/东湖存在明显差异，OOD 检测目前只能提示“像不像”，还不能告诉系统该采什么样的样本；
- 当前不是东湖本地验证，也没有可靠的未来预报能力。

所以本项目的正确定位是：**一套统计上诚实、可复现、可继续接入东湖数据的研究基线**，不是已经完成东湖部署验收的最终模型。
