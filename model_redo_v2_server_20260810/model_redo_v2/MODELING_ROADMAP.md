# 模型构建与验证实施路线

本路线把设计变成可执行实验。顺序不可随意跳过：先冻结标签、特征与切分，再比较架构；locked test 不参与任何选择。

## 阶段 0：建立不可变数据契约

### 产物

- `data_version.json`：所有输入表路径、字节数、行列数和 SHA-256；
- `label_intervals.parquet`：`record_id, target_kind, lower_ug_l, upper_ug_l, censor_type, limit_source`；
- `feature_panels.yaml`：P0–P4 白名单、单位、部署可得时间和有效范围；
- `exclusion_ledger.csv`：每条被隔离记录的原因，不删除源数据；
- `source_registry.csv`：来源、方法、矩阵、LOD/LOQ、地理和时间范围；
- 单元测试：total MC/MC-LR 不混合、单位转换、负值隔离、上下界合法、禁止特征不入模。

### 必做审计

1. 回查 MC-LR 的 12 个负值和所有极端浓度；
2. 对 `ND` 但无 LOD/LOQ 的记录单独分类；
3. 确认 tissue、SPATT、细胞配额、qPCR、传感器信号没有进入水体 µg/L 任务；
4. 对近重复记录建立 canonical duplicate group；
5. 将 bloom proxy 标记为 `available_at_prediction_time`。

完成门槛：所有标签均有可解释状态；若关键来源的单位或矩阵不明，先隔离再训练，不猜测。

## 阶段 1：冻结非 IID 数据切分

### 1.1 外层评价套件

每个任务至少维护三套独立外层评价：

| 套件 | 切分单位 | 回答的问题 |
|---|---|---|
| `source_ood` | 完整 `dataset_id`/检测项目 | 新来源或新方法是否可泛化 |
| `waterbody_ood` | 完整湖泊/水体/站点组 | 新地点是否可泛化 |
| `temporal_ood` | 每来源的后段年份或滚动时间窗 | 未来时间是否可泛化 |

同一 duplicate group、同一水体同一时间窗的记录不得跨外层折。内层调参使用与外层相同类型的 GroupKFold 或 forward-chaining；不允许外层按来源、内层却随机拆行。

### 1.2 total MC 切分要求

- 样本足够的来源做 leave-one-source-out 或来源组合外留；
- NARS 调查周期按 cycle 外推，不把同一湖泊近似重复调查随机拆开；
- Lake Erie 等连续来源用历史 → 未来的滚动切分；
- 美国/加拿大宏平均分别报告，但加拿大样本少时不作强统计结论。

### 1.3 MC-LR 切分要求

- Uruguay 2,393/2,837 的动态记录不能随机分到所有折；至少保留完整来源外测试；
- EMLS 按国家或湖泊分组；
- Sacramento/WQP 的删失和标签稀疏面板单独评价；
- “有完整动态特征的检出子集”与“含删失的静态子集”分别报告，不混成一个数字。

### 1.4 locked test

从外层套件中预先选择一次性验收折，保存 record ID 和哈希。开发阶段只查看 validation suites 的聚合结果；locked test 在模型、特征、集成、校准、阈值全部冻结后运行一次。

完成门槛：自动测试证明所有分组互斥；随机种子变化不改变 locked test 成员。

## 阶段 2：数据和评估基线

实验编号建议：

| 实验 | 内容 | 目的 |
|---|---|---|
| B00 | 训练折中位数/来源不可知 Dummy | 最低性能地板 |
| B01 | ElasticNet + 训练折插补 | 线性可解释基线 |
| B02 | Random Forest | 旧流程对照 |
| B03 | CatBoost | 强缺失/类别树基线 |
| B04 | LightGBM | 强 GBDT 基线 |
| B05 | 普通 XGBoost | 与 AFT 的增益归因 |
| B06 | NGBoost | 概率基线 |

每个模型固定跑 `core_field`、`static_context`、`bloom_augmented` 三套面板。预处理器只在训练折拟合；类别编码、缩放、插补和目标变换进入同一 Pipeline。

完成门槛：指标脚本、折外预测、模型保存、复现实验日志和最差来源报告全部工作。基线不以最高 R² 为唯一选择。

## 阶段 3：删失建模实验

### 实验矩阵

| 实验 | 标签处理 | 模型 |
|---|---|---|
| C00 | 删除 ND | 强树，只作偏差对照 |
| C01 | 0 / LOD/2 / LOD | 多重敏感性，不作主结果 |
| C02 | Hurdle | 检出分类 + 条件浓度 |
| C03 | 区间删失 | XGBoost AFT 三种分布 |
| C04 | 区间删失 | TabM 异方差 log-normal |
| C05 | 区间删失 | TabM mixture / 分位数 |

### 诊断

- 精确值与删失值分别计算 likelihood；
- 按来源、LOD、方法和浓度区间画校准/PIT 诊断；
- 比较高浓度尾部、低浓度覆盖和预测区间宽度；
- 对 LOD 不明记录的纳入规则做敏感性分析；
- 用来源块 bootstrap 而不是逐行 bootstrap 计算置信区间。

完成门槛：主模型在 interval NLL、校准和非 IID 点指标上优于 LOD/2 基线；若分布失配，则保留分位数/mixture，不强行接受 AFT。

## 阶段 4：多任务和前沿模型

### 4.1 多任务消融

| 实验 | 共享方式 |
|---|---|
| M00 | total MC 与 MC-LR 完全单任务 |
| M01 | total MC 预训练 → MC-LR 微调 |
| M02 | 共享编码器 + 分析物独立头 |
| M03 | M02 + 来源均衡批次 |
| M04 | M03 + GroupDRO/正则 |

只根据 MC-LR 的来源外性能判断迁移是否有效。若 total MC 提升而 MC-LR 下降，视为负迁移并回退 M00。

### 4.2 前沿挑战者

- `F00 TabICLv2`：默认回归，统一输入预算；
- `F01 TabICLv2-quantile/fine-tune`：仅在许可和算力满足时；
- `F02 RealMLP multi-quantile`；
- `F03 TabM point/quantile`；
- `F04 TabPFN-3`：仅研究许可审计后运行；
- `F05 TabR`：检索库严格限制为训练折，按水体和时间审计近邻。

公平性要求：同一外层折、同一特征面板、同一标签规则、记录训练/推理时间。TFM 无法原生利用删失区间时，其标签近似方案必须单独标注，不能与 C03/C04 的统计目标混淆。

完成门槛：候选在至少两类非 IID 套件上稳定有增益，且增益不是由同步 bloom proxy 或地理 ID 造成。

## 阶段 5：中国域、OOD 和主动采样

### 5.1 域偏移报告

- 只选美国/加拿大与中国都存在且量纲一致的共同特征；
- 比较单变量分布、缺失模式、相关结构和域分类 AUC；
- 输出每条中国记录的 OOD 分数和最近训练域距离；
- 检查 density ratio 的有效样本量，过小则禁止加权推断。

### 5.2 域适配消融

1. 无适配；
2. 截断 importance weighting；
3. CORAL/MMD；
4. 中国无标签掩码预训练 → 有标签微调；
5. 只有取得东湖标签后，做少样本监督校准。

前四项只能改善迁移候选或不确定度，不能替代第五项的本地验证。

### 5.3 主动采样

按以下综合得分选择东湖采样点/时段：OOD 高、预测区间宽、超阈值概率接近决策边界、季节/湖区覆盖不足、历史高风险。采样设计必须覆盖未检出、常规和高浓度，不只追水华峰值。

完成门槛：给出可执行的东湖采样表和预期信息增益；没有本地标签时，模型卡明确标为外域。

## 阶段 6：集成、校准与最终模型选择

### 6.1 折外集成

- 候选池最多保留 3–4 个互补模型，避免几十模型搜索造成过拟合；
- 权重非负且和为 1；
- `target_kind × feature_panel` 独立学习权重；
- 目标函数以来源宏平均 interval NLL/MAE 为主，加入 worst-group 惩罚；
- 只有折外残差相关性较低且带来稳定增益的模型进入 ensemble。

### 6.2 校准

- 留出独立 calibration fold；
- 比较全局 CQR、来源/季节 Mondrian CQR、截断加权 CQR；
- 报告 50/80/90/95% 经验覆盖与宽度；
- 超阈值概率做 isotonic/Platt calibration 时只用训练域校准折；
- OOD 高时提高不确定度或拒绝，而不是外推置信。

### 6.3 模型选择规则

主排序建议：

1. 来源宏平均 interval NLL；
2. 来源宏平均 log-MAE；
3. 最差来源高风险召回；
4. 90% 区间覆盖偏差和宽度；
5. 模型复杂度、推理成本、许可和解释性。

使用外层组级 paired bootstrap 给出差值置信区间。若复杂模型对最佳简单模型的优势不稳定或很小，选择简单模型。

完成门槛：架构、超参数、特征、阈值、校准和版本全部冻结，才允许进入 locked test。

## 阶段 7：locked test 与东湖前瞻验证

### 7.1 locked test

- 只执行一次；
- 同时输出总体、来源宏平均、最差来源、时间外推、极端事件和校准结果；
- 结果不理想时记录失败并发布该版本，不能返回调参后重复使用同一 test。

### 7.2 东湖验证

至少需要：

- 不同湖区、季节和水华阶段的 total MC 与 MC-LR 实测；
- 同日/严格先验水质、气象和水文；
- 完整 LOD/LOQ、方法、样品组分；
- 一部分样本只用于最后本地测试；
- 工程菌传感器与实验室参考方法的平行样本。

只有本地测试通过，才将“武汉东湖适用性”从研究候选升级为部署模型。

## 阶段 8：工程菌传感器融合

独立建立层次剂量—响应模型：

- 固定效应：log(MC-LR)、响应时间、温度、pH、盐度和交叉反应物；
- 随机效应：批次、培养、设备和重复；
- 输出：`p(signal | concentration, conditions)` 或反演后浓度分布；
- 用实验室参考浓度校准，不以环境模型预测作训练真值；
- 将环境先验与传感器 likelihood 做透明的概率融合，并报告各自贡献。

## 实验基础设施要求

每次运行保存：

- Git commit、数据/切分/特征哈希；
- 环境 lock、CPU/GPU 型号、运行时间；
- 完整配置、随机种子、折成员；
- 折内与折外预测、模型权重、校准器；
- 指标 JSON、来源级明细、置信区间；
- SHAP/Permutation importance、残差与校准图；
- 失败实验和错误日志。

推荐先在 CPU 完成树模型和切分验证，再使用 GPU 运行 TabM/TabICLv2。不要在数据契约仍变化时消耗大规模 GPU 预算。

## 新数据 Agent 的接入规则

Agent 每次交付新数据后，先进入隔离区并完成：分析物、矩阵、单位、方法、LOD/LOQ、日期、坐标、重复、许可和哈希审计。随后重新生成数据画像和切分，但不得改变已冻结 locked test；若新增数据与 locked test 同源/重复，必须排除或建立全新的测试版本。

当前最高价值新增数据仍是：

1. 东湖/武汉同日 MC-LR + total MC + 水质真值；
2. 中国湖泊毒素与完整水质配对；
3. 严格滞后的动态气象/水文/遥感；
4. 高浓度事件与检测方法元数据；
5. 工程菌 MC-LR 原始标定和干扰实验。
