## RV-01 → V0.1：问题形式化（把"最快投放"翻译成可计算问题）

- **审查范围**：需求再解读——"使无人机最快投放"的语义：① 每架无人机"快"；② 全局"先救高风险"；③ 载荷/电量受限；④ 警报动态到达；⑤ 水域与风环境约束。
- **发现**：这不是单机 TSP，也不是标准 CVRP：**存在多停机坪（岸边基地）、异构无人机、软时间窗（毒素窗口）、风险权重、能量（含返程）、多访问（补货）**。公开教材中最接近的表述是 Multi-Depot Vehicle Routing Problem with Time Windows（MDVRPTW）的扩展。
- **决策**：将问题正式定义为 **MD-MUAV-VRPTWP + 能量约束（E）**，记为 `MD-MUAV-VRPTWP-E`；目标采用"风险加权完成时间 + 惩罚项"。
- **影响**：整个模型栈的输入/输出接口由此确定（Instance/Scene → 解 → 统一评分器）。

## RV-02 → V0.2：求解方法谱系审查（精确/启发式/学习式）

- **审查范围**：MIP 精确求解（Gurobi/CP-SAT）、元启发式（GA/PSO/ACO/LKH/PyVRP-HGS）、学习式（NCO：AM/POMO/RRNCO）。
- **发现**：① 实例规模小（10~50 风险点）——精确式"可行"，但**在线重规划要求毫秒~秒级**，MIP 热启动不友好；② 元启发式解质量高但每次 0.1~10s，不满足"警报到达即刻响应+频度重规划"；③ 学习式构造解**前向一次 = 微秒~毫秒级**，且可被局部搜索精修（文献 1.18 的 DRL+DE 两段式即此思想）。
- **决策**：主架构 = **学习式构造策略网络**；基线 = 贪心 + OR-Tools；精修 = 轻量局部搜索。三者共用同一评分器，保证可比。
- **影响**：确定"NN 初解 + LS 精修 + OR-Tools 参考"的三层对比格局。

## RV-03 → V0.3：层级边界（任务级 vs 轨迹级）

- **审查范围**：多无人机任务规划的"任务分配—路径排序—轨迹生成—底层控制"全栈分工（文献 1.11 综述、1.12 覆盖规划）。
- **发现**：本课题的差异化价值与可验证性都在**任务级**（哪些点分配给哪架机、按什么顺序、何时补货）；轨迹级（避障、精确悬停）由飞控层与独立导航模块负责，混入本模型会稀释主目标。
- **决策**：模型只输出**任务级解**（每架机的访问序列 + 补货回站），轨迹级作为接口预留（`coverage/避障接口`）。
- **影响**：模型规模小、可解释、易与现有 web 演示系统对接。

## RV-04 → V0.4：状态表示（欧氏 vs 边特征 vs 图）

- **审查范围**：节点坐标作为唯一输入是否足以编码"物理上更快"？湖面风、机型速度、岸线距离都会造成**方向不对称**（顺风 6 min ↔ 逆风 10 min）。
- **发现**：文献 1.3（RRNCO）与 1.9/1.10（风致不对称）一致指出：纯欧氏是 NCO sim-to-real gap 的**主因之一**；不对称成本矩阵必须进入模型，否则策略学会的是"欧氏距离最优"而非"真实时间最优"。
- **决策**：输入 = 节点特征（坐标归一化 + 风险 + 软窗 + 需求）**外加预计算成本矩阵 T[k,i,j]**（每机、风修正、非对称）；策略网络以"成本感知"方式通过 GNN 式掩码/注意力融合边信息（本实现以掩码+上下文实现；更强的 ANE 边注意力列为 V2.7 候选）。
- **影响**：新增 fig4（非对称矩阵）作为证据；训练/评估全部使用真实或风况采样的 T，阻断 sim-to-real 主因。

## RV-05 → V0.5：目标函数审查

- **审查范围**：备选目标：makespan（最晚到）、总飞行时间、Σw·t（风险加权）、迟到惩罚、未服务惩罚。
- **发现**：① 只最小化 makespan 会退化为"均匀分摊，忽略风险级差"；② 只最小化总时间会"先近后远"，可能怠慢高风险点；③ 应急语义 = **风险加权完成的期望最早** → Σ w_i·t_i 是鲁棒主目标；④ 但必须叠加软窗迟到惩罚（毒素超过窗口后风险主导）与未服务惩罚（防"干脆不服务"）；⑤ makespan 需要弱系数以反映"全部收尾"的运维意义。
- **决策**：`Objective = Σ w_i·t_i + λ·Σ w_i·max(0,t_i−l_i) + μ·makespan + ν·Σ(未服务 w_i)`，默认 λ=2.0、μ=0.05、ν=50（灵敏度实验见报告 §5.4）。
- **影响**：所有方法统一按此评分；指标输出另给 rwt/makespan/served 便于解读。

## RV-06 → V0.6：时间窗性质（硬 vs 软）

- **审查范围**：风险点在"何时失效"？MC-LR 降解窗口是否构成硬截止？
- **发现**：湿实验与风险模型表明**毒素浓度是连续演化的**（trigger1 峰值 2h；扩散需要时间），不存在离散"硬截止时刻"；但**越晚投放，降解前累积风险越大**——这是典型的**软窗+惩罚**结构；文献 1.4（SVRPTW）正是把"经验时间窗"处理为惩罚。
- **决策**：采用软窗：风险越高 → 软窗越紧（窗宽 ∝ 1−w）；窗内无惩罚，窗外按 λ·w 线性惩罚（可扩展到凸/分段）。
- **影响**：窗参数由风险等级解析生成，可解释、可调、可被上游预测模型改写。

## RV-07 → V0.7：编码器选择（逐点 FC / 注意力 / GNN / 图卷积）

- **审查范围**：节点数 10~50、特征数少、但存在"全局依赖"（一架机去哪影响其他机）的三类编码器。
- **发现**：① 逐点共享 FC 无法建模机间耦合与"距离拓扑"；② 纯 GNN 需人工距离邻接，且对本规模增益有限；③ **AM 式 Transformer**（文献 1.1）在 TSP/CVRP/VRPTW 上验证充分、实现简单、对 n≤200 计算开销小，且与 POMO（文献 1.2）兼容。
- **决策**：编码器 = 输入投影(6 维特征)+类型嵌入 → **L=3 层 Transformer（d=128，H=8，FF=512）**；图级嵌入取均值池化作为全局上下文。
- **影响**：参数量约 46 万（d=128）~ 26 万（d=96），CPU 每次前向 <5 ms（n=13），满足边缘部署。

## RV-08 → V0.8：解码器结构（逐机串行 vs 联合选择）

- **审查范围**：多无人机构造式解码的两种主流：① 串行（一架机一条路线，用容量/距离分割）；② 联合（每步选 (k,j) 对）。
- **发现**：① 串行把"机间竞争"隐式转化为顺序先验，多车位情况下次优；② 联合选择与"时间同步"天然一致（各机的时间/电量状态各自独立维护，仅共享"哪些任务已服务"的全局场），且 POMO 的"多起点"可迁移为"多机起点"；③ 文献 1.7 的异构车辆嵌入=把车辆特征并入上下文，正好与本模型的 dyn=[载荷,电量,时间] 特征化对齐。
- **决策**：解码器 = **每步对 (k,j) 联合打分**：上下文 = 图均值嵌入 + 各机当前节点嵌入 + 各机动态特征（cap_rem, en_rem, t_now），打分 = 上下文·节点嵌入（按 d 缩放），掩码后 softmax/采样。
- **影响**：动作空间 = m×n（3×13=39），构造步数 ≤ 2·Σ需求 + 补货次数，样本高效。

## RV-09 → V0.9：掩码体系（可行性五元组）

- **审查范围**：哪些 (k,j) 组合必须是"不可行"？少掩一个=产生不可行解污染训练；多掩一个=可能剪掉好解。
- **发现**（逐项审计）：① 需求掩码：任务已服务完；② 载荷掩码：load_k=0 时任务不可选；③ **能量掩码（关键）**：只检查"能飞到 j"不够——**必须保证"任意时刻还能飞回所属停机坪"**（返航安全），即 leg(k,cur→j)+leg(k,j→depot_k) ≤ E_rem；④ 时间掩码：t+leg ≤ 计划时域；⑤ 停机坪归属掩码：只允许回本机所属停机坪，且仅在"载荷空或电量低"时允许（防止空转循环）。
- **决策**：五类掩码全部实现于同一 `infeasible(B,m,n)` 张量；训练与推理共用；`env.simulate` 另行冗余审计 feasible 标志。
- **影响**：生成解**保证**可行（能量安全），训练无坏样本；也解释了 fig5 曲线为何无剧烈震荡（见训练日志）。

## RV-10 → V1.0：多访问/补货（Multi-trip）

- **审查范围**：单航次 vs 多航次：载荷 4~6 包 < 需求 10+ 点时，是否允许回站补货再出发？文献 1.8（多访问异构无人机 VRP）与 1.7（EV 补能）都支持"回访/补能"。
- **发现**：若禁止补货，模拟场景将经常"服务不完"（ν 惩罚占主导），策略学成"保重点"而丢失"全覆盖快速"语义——与业务"最快投放"不符；允许补货后解空间增大，但掩码已保证安全，训练可学。
- **决策**：depot 作为显式**补货动作**（回站耗时 = T[cur→depot] + refill 12 min，重置载荷与电量）；允许对同一任务**多次访问**（需求≥2：多包协同降解/大热点多架投放）。
- **影响**：路线中可含 0 个或多个 depot 补货节点；与"无人机回收替换检测装置"的运维流程兼容。

## RV-11 → V1.1：训练算法（baseline 与采样策略）

- **审查范围**：REINFORCE 基线选择：value 网络 / 贪心 rollout（Kool）/ 多采样共享基线（POMO）；方差与样本效率。
- **发现**：① value 网络引入第二套网络且对偶发好解敏感；② rollout baseline 需要周期性推理 2 次；③ **POMO 式"相同实例 S 个采样共享均值基线"**（文献 1.2）：同一实例上 S 条轨迹的均值作为基线，方差低、实现简单、无额外网络，且天然鼓励"找到最好轨迹"。
- **决策**：POMO-lite：每实例采样 S=8（可扩至 64），基线 = 这 S 条的目标均值；优势 = 基线 − 轨迹目标；损失 = −(优势·logp) 均值；Adam lr=1e-4，梯度裁剪 1.0。
- **影响**：训练无监督标签、直接优化目标；3000 步内收敛（见 fig5）。

## RV-12 → V1.2：训练数据（分布决定成败）

- **审查范围**：训练用什么实例分布？纯随机均匀（AM 风格）会导致"只会解均匀点"；只用 14 装置点会导致过拟合。
- **发现**：文献 1.3 警示"oversimplified Euclidean data"；本课题有**真实环境信号**：OSM 东湖水多边形（空间）、Open-Meteo 风场（时间）、14 装置坐标+浓度（先验）——把它们合成"东湖分布"实例，风险点按装置包围盒均匀采样、浓度加权（30% 高 / 40% 中 / 30% 低）、风况按小时随机采样 → **训练分布≈部署分布**。
- **决策**：实例生成器 `scenario.build_eastlake(seed, wind_hour)`；n_task ∈ {8,10,12} 混训（规模泛化）；保留公共基准（Solomon/PyVRP MDVRPTW）做**分布外压力测试**。
- **影响**：训练/评估/报告图全部基于东湖分布（fig3），论文级可复现。

## RV-13 → V1.3：奖励塑形（终局 vs 传递）

- **审查范围**：构造式解码的奖励形态：逐步奖励（每步给 ∝ 风险*时间增量）vs 终局奖励。
- **发现**：① 逐步奖励可加速Credit Assignment但**与真实目标不等价**（局部贪心最优≠全局最优），且参数难调；② 构造式解码步数少（≤30），终局奖励的方差可用 POMO 基线压下；③ 用统一 `objective()` 让"训练与评估同目标"是可比性的先决条件。
- **决策**：**终局奖励**（−objective），无塑形；若未来训练困难，再按"风险加权时间增量惩罚"做辅助项（列于未来方向）。
- **影响**：简化训练管线，且"训练目标=评估目标"保证了曲线可信。

## RV-14 → V1.4：可行性保障与审计

- **审查范围**：训练中策略可能"反事实制造不可行"（如电量被耗到无法返航）如何兜底？
- **发现**：① 掩码已从动作空间中剔除不可行；② 但仍需**双保险**：`env.objective_times` 返回 feasible 标志，任何解（含基线解）都审计；③ 对仍不可行的解（不应发生），按未服务惩罚处理并在日志打出。
- **决策**：掩码（动作前）+ 审计（解后）双层机制；报告 §5.2 给出全部实验解的 feasible 统计。
- **影响**：可信度：实验中所有方法的解 100% 可行（能量安全意义下）。

## RV-15 → V1.5：物理模型（风与能量）

- **审查范围**：时间/能量模型：纯几何距离 × 常数速度是最粗糙的；文献 1.9/1.10 给出"前地速矢量叠加"与"鲁棒能量预算"两个可移植公式。
- **发现**：① 时间：沿航向分解风速 v_par，地速 v_g = √(v_air² − (|v_wind|² − v_par²)) + v_par，t = d·safety / v_g；safety=1.25 近似航线曲折系数；② 能量：以"飞行分钟"为能量单位（E_k=28~34 min），每次在航前检查"剩余 ≥ 该步 + 返航"（隐式 30% 储备）；③ 风速数据来源于 Open-Meteo（已下载 2024 夏 2928 小时）。
- **决策**：按上述实现 `wind_time_matrix`；每数据小时采样一个风况生成实例（训练+评估均匀覆盖）。
- **影响**：fig4 直接展示非对称性；消融"无风 vs 有风"见 §5.4（证明模型确实利用风信息）。

## RV-16 → V1.6：异构机队

- **审查范围**：机队是否均质？哪类异构最重要？
- **发现**：①`载荷`差异（4 包 vs 6 包）直接改变可行解结构；②`电量/速度`差异少量（13~15 m/s）；③ 文献 1.7 对异构车辆的嵌入做法可平移。
- **决策**：每机独立 T 矩阵（速度因子缩放）＋ 独立 cap/energy 向量；模型上下文含每机动态特征；异构通过"每机一条上下文"自然编码。
- **影响**：部署时只需替换参数向量即可适配不同机型，无需重训。

## RV-17 → V1.7：动态警报与重规划

- **审查范围**：警报是事件流（泊松到达 + 风险演化），静态解必然失效；重规划粒度（全量 vs 增量）与触发策略是什么？
- **发现**：文献 1.17/1.20 的共识是**事件驱动 + 增量修正**；文献 1.19 的两阶段（预规划+在线插入）工程验证充分。
- **决策**：架构 = 滚动时域：① 静态规划 = 当前已知任务解；② 新警报/偏差/预测修正 → 触发**重规划**：优先把新点**插入**既有解（最小扰动），若收益 > 阈值再全量重解（本模型毫秒级，全量重解代价可忽略）；③ 已派出无人机只对**未执行段**重排。
- **影响**：闭环（fig7）与"最快投放"的最终语义绑定：每一时刻均按"当前信息最优"执行。

## RV-18 → V1.8：评估协议（可比性危机）

- **审查范围**：如何公平比较 NN 与 OR 与贪心？不同实现有不同目标/约束定义时最易"各说各话"。
- **发现**：必须**三同**：同输入（Instance）、同评分器（`objective()`）、同指标（rwt/makespan/served/obj/solve_time）。
- **决策**：所有求解器输出 `routes: list[list[int]]` → 统一 `objective_times/objective/risk_weighted_time` 评分；固定种子 16 个测试场景（seed 9000+，含不同风况），报均值±标准差；另附"基准实例压力测试"。
- **影响**：报告 §5.3 表格具备抗辩力。

## RV-19 → V1.9：基线选择（两个必须）

- **审查范围**：有"公平基线"才有意义；贪心（最近+风险加权）与工业标准 OR-Tools 缺一不可。
- **发现（关键限制）**：OR-Tools 原生目标为"总弧成本"，**无法直接表达 Σw·t**；采用代理：弧代价 = T[i,j]·(1+γ·w_j) + 软上界惩罚（`SetCumulVarSoftUpperBound`）＋ span 系数近似 makespan；**OR-Tools 侧重不同目标**，其 rwt 结果仅作为"工业实现参考下界/上界对比"（报告中如实说明）。
- **决策**：贪心基线（γ=1.0）+ OR-Tools（代理目标，5s 时间预算）＋ 两者各自 + 局部搜索版本，共 4-5 行结果。
- **影响**：报告给出"代理目标偏差"分析，增强诚实性与科学性。

## RV-20 → V2.0：后处理（学习初解 + 局部搜索）

- **审查范围**：构造式解可直接用吗？文献 1.18（DRL 初解 + DE 精修）表明 90% 场景"解码质量还差临门一脚"。
- **发现**：① NN 构造解为"好种子"；② 简单 2-opt（线路内逆序）+ relocate（跨机移动）"改进即接受"即可平均再降 5-15% 目标；③ 该后处理与问题规模无关，成本毫秒级。
- **决策**：默认执行"NN → LS(800 次改进迭代, 2s 上限)"；同样作用于贪心基线（保证对照公平）。
- **影响**：报告 §5.3 中 rl_ls / greedy_ls 列即此产物。

## RV-21 → V2.1：与上游预测的联动（SPO）

- **审查范围**：上游"MC-LR 风险预测"若只喂给模型当输入，预测误差将不变地放大为调度误差（先预测后优化的经典次优）。
- **发现**：文献 1.6（SPO）给出一条可操作路径：定义**决策后悔**（预测-优化联合损失），用不对称损失惩罚"假阴性（预测低风险但实际爆发）>假阳性（预测高风险但未爆发）"。
- **决策**：本版落地为**输入层面的软联动**（风险 w 作为特征 + 软窗由预测驱动），SPO 联合训练列入"尚未尝试/D2 阶段"（需上游预测器可微调）。
- **影响**：为未来"预测-规划一体化"预留了接口与损失设计，且不阻塞当前版本交付。

## RV-22 → V2.2：泛化与迁移（RRNCO 缺口）

## RV-23 → V2.3：部署与算力（边缘推理）

- **审查范围**：模型跑在哪？机载/岸边边缘/云端？通信与延迟如何预算？（文献 1.21 的端边云分层）

## RV-24 → V2.4：退化场景（密集风险 → 覆盖问题）

## RV-25 → V2.5：鲁棒性与安全冗余

- **决策**：本版提供"邻机接管"逻辑与接口；CBBA/容错共识列为未来（V3 候选）。
- **影响**：向导师/评审展示时可直接演示"模拟故障→自动改道"。

## RV-28 → V2.7：边特征三件套（文献 1.3 RRNCO 直接驱动）

- **审查范围**：RRNCO Table 1 证据——节点式 POMO 在非对称 ATSP gap 34.2%（对称场景 1–4%）；ACVRPTW 12.56% vs RRNCO 3.74%；其粒度消融：去 Φ 方向角模态 gap 3.74→4.06%（OOD 更甚）。

  ② 解码 logits = C·tanh(q·hᵀ/√d) − β·log(T_leg/T_scale)（C=10，β 可学习初值 1）——RRNCO 式 21 的 tanh 截断 + 负对数距离先验，直接把"现在去 j 的实测成本"注入决策分数。

## RV-29 → V2.7：×8 推理增广（文献 1.2 POMO 驱动）

- **发现**：POMO Table 5——×8 增广（镜像/旋转）≈ 采样 1280 条质量，成本仅 ×8 前向。本模型存在**两种精确对称**：① 风逆转 w→−w：T'[i,j]=T[j,i]（速度三角形对航向反对称，已验证数值相等）；② xy 镜像（x→−x / y→−y：T 不变，仅几何特征镜像）。2×2×2=8 变体。
- **决策**：evaluate.augment8 实现 8 变体，每变体采样 n/8 条，全部回原实例评分取最优；--augment 开关。

## RV-30 → V2.7：真 POMO 锚定（文献 1.2 的"共享基线"本质）

- **发现**：POMO 的共享基线不仅是"同实例多采样"，更关键的是**轨迹起点异质**（多起点策略优化）；本实现是 iid 采样共享基线（Kool "buy 4 samples" 版）。
- **决策**：train.py --anchor——每个实例的 S 条轨迹第 0 步强制"无人机0 的首目标 = 任务 s"（s 轮换），其余动作屏蔽；梯度经被迫动作的 logits 正常流动（POMO 同款）。
- **影响**：优势零均值化 + 抗局部最优；若同网络纯训练可达 POMO 报告的 3.51%→1.07% 量级改进（TSP100），即为白拿收益。

## RV-31/32 → V2.7：v3.0 任务契约 + 治理生效目标（report/06 §5 落地）

- **审查范围**：06 报告的 6 个失配点（任务几何来源/需求物理推导/时间窗来源/目标时滞/级联不确定度/空间尺度）。
- **决策**：
  ① **flow_tasks.py**：消费水流模型 opt_result.npz（792 候选点、scores、member_scores、patch 563 格=1.41 km²）+ 降解模型参数（k_base=0.25 h⁻¹、f_D 剂量增强、T_DRIFT=60 min、T_LIMIT=360 min）→ 生成规划 Instance：投放点 = cands 按 score 降序 + 300 m 去耦（=2·R_eff，R_eff=√(A_drop/π)≈143 m）；需求 d_j = ⌈D*(C₀,T_limit)⌉ 包（C₀ 高→多包，实测 1–6）；窗口 l_j = T_limit=360 min；时滞 eff_lag = T_DRIFT + t_safe(D_j, C₀)。
