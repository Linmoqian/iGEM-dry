## 1. 总体判断

阶段 8 的结果有审计价值，但还不能支持"重建 MC-LR 浓度预测模型"这一主叙事，更不能支持中国湖泊部署。

当前最可靠的部分不是 MC-LR，而是 Lake Erie 数据集内的总微囊藻毒素 / 总 MC 同步估计模型。如果 17–18 个特征中包含同步测得的蓝藻叶绿素、浮游植物分类叶绿素，那么 RF R²=0.43–0.44 更像是在捕捉"同一时刻蓝藻生物量与总 MC 的相关性"，不等价于可提前预警的 MC-LR 浓度预测。

Decision 003 的任务拆分是正确方向。现在必须进一步把论文/报告主线改成：
"当前项目尚未建立稳健的 MC-LR 泛化预测模型；已建立的是若干数据集内总 MC baseline，并识别出 MC-LR 建模受样本量、零值/检出限、检测方法与跨域差异限制。"

这不是失败，反而是更可信的科研结论。

## 2. 主要问题

1. **任务名称与可支撑证据不匹配**：不能用总 MC 模型的表现来证明 MC-LR 模型有效。
2. **Lake Erie 模型存在"近标签代理变量"风险**：蓝藻叶绿素与 MC 同步采样时，模型更像是诊断性估计而非预测。
3. **HABs NLA 的随机划分 R²=0.23 不够可信**：必须做 GroupKFold by DSGN_CYCLE。
4. **EMLS MC-LR 的 54% 零值不能简单当作真实零**：是核心风险，不是普通预处理细节。
5. **跨数据集泛化失败不能直接解释为"生态差异"**：R²=-19M 首先应怀疑 pipeline 问题。

## 3. 高风险点

1. 把同步估计包装成提前预测
2. 总 MC 与 MC-LR 标签混用
3. EMLS 测试集 17 行导致不稳定
4. 辅助分类任务指标不匹配
5. 中国湖泊部署没有证据链

## 4. 必须修改项

1. 修改项目主叙事
2. 建立数据集—目标变量合同
3. 重跑 HABs NLA 的分组验证
4. 重新定义 Lake Erie 的两个版本（A1 同步估计 / A2 提前预测）
5. 对蓝藻叶绿素做特征可用性审计
6. EMLS 必须处理左删失/零值问题
7. 复核跨数据集泛化 pipeline
8. 分类任务必须报告 PR-AUC、Recall、Precision、F1

## 5. 可选优化项

1. 把模型目标从"浓度精确回归"改成"风险分层 + 浓度区间"
2. 增加 baseline 家族（ElasticNet、HuberRegressor、Quantile Regression、Tobit）
3. 增加"简单经验模型"作为强基线
4. 报告不确定性（bootstrap / repeated CV）
5. 做错误样本分析
6. 把跨数据集失败变成论文贡献

## 6. GPT 可能错在哪里

1. 蓝藻叶绿素不一定是泄漏（如果来自预测日前的在线荧光探头）
2. HABs R²=0.23 不一定严重高估（需 GroupKFold 验证）
3. EMLS 零值可能有一部分是真实零
4. 跨数据集失败不一定全是生态差异（可能是工程问题）
5. 中国场景并非完全不能做（研究型原型 vs 实际部署）

## 7. 下一步建议

1. 做数据与任务审计表
2. 重跑验证矩阵
3. 给 Lake Erie 建两个版本（A1/A2）
4. EMLS 暂停复杂模型，先解决零值与样本量
5. 跨数据集泛化先查 bug，再谈科学解释
6. 中国部署结论改成"不可直接部署，需要本地校准"
