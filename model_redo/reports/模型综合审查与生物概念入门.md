# iGEM 蓝藻毒素模型综合审查与生物概念入门

> 审查范围：`model/`、`model_redo/` 中的代码、配置、数据说明、清洗产物、划分文件与实验结果。  
> 审查日期：2026-08-05。  
> 面向读者：刚进入蓝藻毒素、生物传感与环境机器学习方向的研究人员。  
> 重要提示：本文是模型和研究设计审查，不替代实验室生物安全、毒素标准品操作规范或饮用水风险管理规范。

## 1. 一页结论

这个项目实际上包含三类不同的问题，目前仓库只部分实现了第一类：

1. **环境软测量（nowcast）**：用同一次采样的叶绿素、蓝藻丰度、营养盐、水温等，估计同一次采样的总微囊藻毒素（total microcystins, total MC）。这是当前代码最接近、数据也最支持的任务。
2. **环境预测（forecast）**：用时刻 `t` 之前可获得的数据预测 `t+h` 的毒素。这才是“提前预警”，但当前特征、时间划分和标签组织还没有真正形成严格的未来预测任务。
3. **工程菌生物传感器模型**：MCLR 被上游识别元件感知，经调控线路和可能的群体感应放大，最后由 GFP/RFP 荧光报告。这需要剂量—响应、时间动力学和湿实验数据；两个文件夹中没有相应数据或模型代码。

因此，不能把当前的树模型成绩直接描述成“工程菌能够预测 MCLR”或“东湖预警模型已经建成”。更准确的阶段性表述是：

> 已完成若干美国湖泊数据上的**总微囊藻毒素环境关联/同步估计原型**，并做了很初步的欧洲湖泊 MC-LR 可行性探索；尚未建立可验证的未来预测模型、工程菌荧光响应模型或武汉东湖本地化模型。

当前最重要的结论如下。

- `model/` 的优点是管线相对模块化、同时尝试分类与回归、包含 XGBoost/LightGBM、SHAP 和多种指标；但随机行划分、测试集参与早停、类别权重硬编码、总 MC 与 MC-LR 混淆，使已有高分不能作为部署证据。
- `model_redo/` 的任务边界和“时间外推”意识明显改善，也加入 Dummy/Ridge 基线；但实现与配置不一致，固定测试集被反复用于模型选择，且存在两个严重单位错误和一个检出限解析错误。
- Lake Erie 的最好结果 `R²≈0.43` 主要是**同次采样软测量**结果，其中包含蓝藻丰度或蓝绿藻叶绿素等强代理变量。它可以作为研究原型，但不能自动解释为提前预测能力。
- EMLS 的 MC-LR 实验只有 17 条测试记录，10 条为零、7 条为正，且没有高浓度事件；`R²≈0.195` 的不确定性很大，不能支持泛化结论。
- HABs/NLA 清洗中的叶绿素 a 和总磷均有 **1000 倍单位错误**；NCCA 中 539 个 `<0.10` 被转成缺失值。因此跨数据集与合并训练结果目前应视为失效，需要修复后全部重跑。
- 工程菌能否在与公共卫生相关的 µg/L 量级感知 MCLR，关键在于**上游识别元件**，而不是选择红色还是绿色荧光蛋白。GFP/RFP 只是输出灯，不会自行识别 MCLR。
- 最终系统应拆成“生物传感校准层—环境时空预测层—风险决策层”，分别验证，再进行端到端集成。

## 2. 项目真正想构建什么

从项目说明、数据选择和前端目标看，期望系统是一个闭环：无人机投放工程菌检测节点，节点采集水质与荧光信号，后台融合环境信息，生成毒素风险估计、地图和预警。

```mermaid
flowchart LR
    A["水体中的 MCLR / 其他微囊藻毒素"] --> B["工程菌识别与信号转导"]
    B --> C["GFP / RFP 荧光输出"]
    C --> D["光学、电化学与常规水质传感"]
    D --> E["校准、质控与浓度反演"]
    E --> F["环境时序/空间模型"]
    F --> G["风险分级、地图与提前预警"]
    G --> H["复核采样与管理决策"]
```

这张图至少包含三种统计模型：

- **传感器反演模型**：从荧光、电压、OD、温度等反演水样中的目标物浓度，并给出检出限和不确定度。
- **环境预测模型**：融合历史毒素、水温、营养盐、气象、水动力、遥感等，预测未来某个时间窗的风险。
- **空间模型**：把有限节点与遥感信息转换成连续风险面。IDW 可以做演示，但科学部署通常还需要空间交叉验证和不确定度。

当前 `model/` 和 `model_redo/` 只覆盖环境表格模型的一部分。仓库中没有以下内容：工程菌线路定义、识别分子、菌株、启动子逻辑、GFP/RFP 原始荧光、OD600、反应时间、温度、标准曲线、空白/阴性/阳性对照、交叉反应实验、传感器噪声或空间插值验证。因此，仅凭这两个目录**无法判断工程菌线路本身是否可行**。

## 3. 首先分清几个容易混淆的目标

| 名称 | 它表示什么 | 是否等于 MC-LR | 本仓库情况 |
|---|---|---:|---|
| total microcystins / total MC | 多种微囊藻毒素异构体/同系物的总量；具体含义依检测方法而异 | 否 | HABs 与 Erie 的主要目标 |
| MC-LR / MCLR | 可变氨基酸位置为亮氨酸（L）和精氨酸（R）的一种具体同系物 | 是 | EMLS、NCCA 中有同系物特异数据 |
| `MICX_DET` | 是否检出微囊藻毒素的二元标签 | 否 | 旧模型分类目标之一 |
| mcy 基因/qPCR | 样本中潜在产毒基因或细胞的信号 | 否 | 只能表示产毒潜力，不能直接等同现时毒素浓度 |
| 蓝藻丰度、藻蓝蛋白、蓝绿藻叶绿素 | 藻华或蓝藻生物量代理 | 否 | 可帮助同步估计，但并不保证有毒，更不能说明是哪种同系物 |

这一区分非常重要。用 total MC 训练的模型不能未经验证就改名为 MCLR 模型；反过来，小规模 MC-LR 数据也不能替代总毒素风险模型。

## 4. 两代模型结构审查

### 4.1 `model/`：第一代通用树模型管线

第一代模型的大致流程为：

```text
原始数据 → 各数据集清洗器 → 统一特征构造 → 随机训练/测试划分
         → XGBoost + LightGBM → 简单平均集成 → 指标、图形、SHAP
```

主要任务：

- 分类：检出/未检出，或按阈值构造风险标签；
- 回归：仅在阳性样本中拟合 `log10(total_mc)`；
- 数据：NLA/HABs、Lake Erie、San Francisco Estuary 等。

已有报告给出的测试结果包括：

| 数据集 | 分类 AUC | 回归 R² | 两倍误差内比例 | 解释限制 |
|---|---:|---:|---:|---|
| HABs/NLA | 0.847 | 0.319 | 49.4% | 随机划分；回归只用阳性样本 |
| Lake Erie | 0.943 | 0.742 | 72.1% | 同次强代理特征、随机划分及测试集早停污染 |
| SF Estuary | 0.811 | 0.329 | — | 测试集约 31 条，极不稳定 |

这些数值是代码和旧报告的历史记录，不应被视为经过独立验证的最终性能。

**值得保留的部分**

- 数据集注册、特征构造、训练、评估和解释模块已经分开，适合继续工程化。
- 同时报告 AUC、PR、RMSE、MAE、R²、两倍误差内比例等，比只看一个 R² 更完整。
- 对浓度做对数变换符合毒素浓度长尾分布的常见特点。
- 树模型能够处理非线性、交互与一部分缺失值；SHAP 有助于排查模型依赖的变量。
- 尝试了多个数据源，而不是只对一个表格追求高分。

**影响结论的主要问题**

1. **测试集参与训练决策。** `model/run_train.py` 把 `X_test/y_test` 传入训练函数用于早停，随后又在同一集合报告测试性能。这相当于模型已经“看过考卷”。交叉验证中也把同一折同时用于早停和计分。
2. **随机行划分不适合环境监测。** 同一湖泊、站点、日期或相邻时间记录可能同时进入训练与测试，导致空间/时间泄漏。真正部署关心的是新年份、新站点或新湖泊。
3. **阳性样本回归带来选择偏差。** HABs 中约 66% 是未检出；只在 1241 条检出记录上拟合浓度，回答的是“已经知道检出后有多高”，而不是完整的发生—浓度问题。
4. **类别权重被硬编码。** XGBoost 的 `scale_pos_weight=1.95` 和 LightGBM 的 `is_unbalance=True` 并未按每个训练折计算。对 Erie 或 SF 这类正类占多数的数据甚至可能朝错误方向加权。
5. **强代理变量可能构成任务泄漏。** 同次采样的蓝绿藻叶绿素、qPCR 或其他毒素相关变量适合做同步软测量，但不能直接进入“未来预测”特征。
6. **集成没有保证优于单模。** 报告中多次出现 XGBoost 或 LightGBM 单模优于简单平均；集成权重没有在独立验证集上学习。
7. **可复现性不足。** `--tune` 参数没有真正实现；没有保留完整模型、预处理器、特征清单和环境锁文件；分类与回归图可能写入相同文件名。

### 4.2 `model_redo/`：重构方向正确，但实现尚未兑现设计承诺

重构文档最终形成了较合理的任务分层：

- 主任务 A：Lake Erie 与 HABs 的 total MC 分类/回归；
- 探索任务 B：EMLS 的 MC-LR 小样本建模，NCCA 外部验证；
- 任务 C：东湖/中国数据只做协变量偏移与可迁移性评估，不能声称已经部署。

它还引入了按时间划分、按国家分组、Dummy/Ridge 基线和多轮实验记录，这是比第一代更科学的方向。

已记录的代表性结果：

| 实验 | 历史最好结果 | 正确解读 |
|---|---:|---|
| Erie，18 个特征，2013–2022 训、2023–2024 测，RF | R²=0.430，Spearman=0.737，两倍内=62.1%，测试 n=531 | 同步软测量原型；含强代理变量，不是未来预报 |
| Erie，去掉蓝绿藻叶绿素后的最优模型 | Ridge R²=0.384，但两倍内仅 33% | 最优算法发生变化，不能简单说所有模型只降到某个单一数值 |
| HABs，扩展特征，XGBoost | R²=0.229，Spearman=0.550，两倍内=37.9%，测试 n=248 | 随机行划分且受单位错误影响，需重跑 |
| EMLS MC-LR，Ridge | R²=0.195，测试 n=17 | 测试样本过少，且 alpha 在同一测试集挑选；不可作为稳定证据 |
| HABs→Erie | 最好约 R²=0.058 | 跨域泛化接近无效 |
| Erie→HABs | 最好约 R²=-4.46；Ridge 极端为约 -1900 万 | 分布与单位严重不一致；极端负值是 Ridge，不代表所有算法 |
| 合并训练 RF | 总体 R²=0.213；Erie 0.290；HABs 0.076 | 合并并没有解决域差异，且受单位错误污染 |

**重构版本的优点**

- 明确承认 total MC 与 MC-LR 是不同目标。
- Lake Erie 至少尝试了向后年份测试，比随机划分更接近部署。
- 引入 DummyRegressor 和 Ridge，能判断复杂模型是否真正提供增益。
- 开始记录实验假设、结果和决策，便于科学复盘。
- 文档中明确提出 locked test 不应用于调参，这个原则本身正确。

**代码与文档不一致**

- `configs/split.yaml` 写的是 70/15/15 和 locked test，实际 `run_split.py` 主要只产生 train/test；HABs 的“分层”函数实际是随机排列。
- 配置写输出 Parquet，实际清洗器写 Pickle。
- README 和配置禁止在 locked test 上选模型，但 `run_train_enhanced.py`、`run_iter2.py`、`run_iter3.py` 反复比较同一测试集；`run_iter2.py` 的 Ridge alpha sweep 直接用测试 R² 选 alpha。
- `src/` 与 `tests/` 基本为空；多个训练脚本复制相同逻辑，后续修复很容易只改到其中一个。
- `models/`、`runs/` 和主要图形目录没有保存可复现的模型包、预测明细与数据版本；当前结果多为 JSON 汇总。
- 依赖版本未精确锁定，现有 Pickle 在不同 NumPy 环境中已出现兼容问题。这也说明长期产物应优先使用 Parquet，模型包应记录库版本。

以下统计来自仓库现有清洗产物的逐列复核，而不是仅抄文档。

| 数据集 | 总行数 | 目标有效情况 | 时空结构 | 适合回答什么 | 主要限制 |
|---|---:|---|---|---|---|
| Lake Erie | 3074 | total MC 有效 2659；33 个零；中位 0.22、最大 46.56 µg/L | 2013–2024，约 82 个非空站点 ID；多项目混合 | Erie 同步估计；修正设计后可探索时间外推 | 13.5% 目标缺失；站点 ID 大量缺失；同站同日/项目重复；检测方法和项目异质 |
| HABs/NLA | 3664 | total MC 定量值 1241；检出标签 3663，其中 2422 未检出 | 2007、2012、2017；3373 个站点 ID | 美国湖泊横截面发生风险与检出后浓度 | 定量目标缺失 66%；三个调查周期；不是连续时间序列；单位清洗错误 |
| EMLS | 369 | MC-LR 有效 352：200 个 0、152 个正值；最大 3.968 µg/L；≥1 仅 13 条 | 27 国、369 个不同湖泊，2015 年夏季单次采样 | 欧洲湖泊 MC-LR 空间关联与小样本可行性 | 不是时间序列；高浓度事件少；生产力较高湖泊有抽样偏向 |

### 5.1 Lake Erie

该数据来自多个监测项目，覆盖 2013-06-18 至 2024-10-22，包含总微囊藻毒素、叶绿素和常规水质。数据的连续年份是优势，但“多个项目拼接”意味着采样频率、站点、分析实验室和缺失机制可能不同。[Lake Erie 官方数据目录](https://catalog.data.gov/dataset/total-microcystins-chlorophyll-and-other-water-quality-data-collected-in-lake-erie-from-20)

仓库中 364 条 `<0.15` 被替换为 0.075 µg/L，即 LOD/2。这可以作为非常粗的敏感性分析，但不应被当作真实测量值。更好的方式是保留 `原始字符串、LOD、是否删失` 三列，并使用删失模型或区间损失。

同一次采样的 `Bluegreen algae-chla µg/l` 等变量与毒素强相关，适合回答“当前样本可能有多高”，但若预警目标是明天或下周，它们必须按真实可用时间戳处理。

### 5.2 HABs/NLA

NLA 是概率抽样的湖泊调查，适合全国尺度横截面推断，而不是天然的逐日预测数据。[EPA NLA 2017 数据与报告](https://www.epa.gov/national-aquatic-resource-surveys/reports-and-data-national-lakes-assessment-2017)

当前存在两个 P0 级单位错误：

- `CHLA_RESULT` 本身是 µg/L，`model_redo/run_clean.py` 却乘以 1000 后命名为 `chla_ugL`；
- `PTL`（总磷）本身是 µg/L，却直接重命名为 `tp_mgL`，正确变换应除以 1000。

EPA 的实验室操作手册明确把叶绿素 a 和总磷报告为 µg/L，而总氮为 mg/L。[NLA 2017 Laboratory Operations Manual](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P100YX9O.TXT)

这两个错误会让 HABs 与 Erie 的“共同特征”相差 1000 倍，足以制造跨域 Ridge 的爆炸预测，并污染合并训练和重要性解释。所有依赖 HABs 清洗表的重构实验必须在修正后重跑。

HABs 中的 `B_G_DENS` 是蓝藻细胞丰度（cells/mL），不是重构代码注释所说的“藻蓝蛋白荧光代理”。两者虽然都可作为蓝藻生物量代理，但测量原理、量纲和误差模型不同，数据字典中不能互换。

### 5.3 EMLS

EMLS 是 2015 年夏季对欧洲 27 个国家 369 个湖泊的一次标准化快照，实验室集中测量 8 种微囊藻毒素同系物。它的标准化程度优于许多拼接数据，但每湖只有一个时间点，不能用于学习“未来几天”的动态。研究本身也说明样本偏向生产力较高的湖泊。[EMLS Scientific Data 数据论文](https://www.nature.com/articles/sdata2018226)

仓库文档曾把 MC-LR 的 0 当成含义不明。原论文说明，无毒素信号的样本被视为不存在该毒素；在所述 250 mL 样品条件下，MC-LR 的检出限约为 0.0086 µg/L。因此这些 0 仍属于“在该方法下未检出”的左删失信息，但不应简单说成未知缺失。

另有一个清洗逻辑错误：`total_mc_ugL` 在重命名 MC-LR 后才对“仍以 MC_ 开头的列”求和，可能把 MC-LR 本身排除在总量之外。必须先建立显式同系物清单，再求和，并使用 `min_count=1` 防止全缺失行被伪造为 0。

### 5.4 NCCA 2015

原始 MCLR 列中有 539 条 `<0.10`。当前代码用 `pd.to_numeric(..., errors="coerce")`，把它们全部变成 NaN，只留下 53 个数值，却又在文档里把 592 行近似描述为有效目标。这是删失数据处理错误。

正确做法不是把 `<0.10` 强行解释成 0.05 后忘记不确定性，而是保存：

- `mclr_observed`：可定量时的数值；
- `mclr_lod=0.10`；
- `mclr_censored=True/False`；
- 评估时先看“预测是否低于 0.10”的分类/区间命中，或采用 Tobit/删失似然。

其 `total_mc_ugL` 也存在相似伪零问题：MCLR 重命名后被排除，其他同系物全缺失时 Pandas `sum` 默认给 0，形成 567 个可能没有分析意义的零值。

## 6. 关键问题分级

### P0：不修复就不能继续引用结果

1. 修复 HABs 叶绿素 a 与总磷的 1000 倍单位错误。
2. 修复 NCCA `<0.10` 的删失解析，并重新定义有效样本数。
3. 修复 EMLS/NCCA total MC 求和遗漏 MC-LR、全缺失变零的问题。
4. 建立真正的 train/validation/locked-test：测试集不能参与算法、特征、阈值、alpha 或超参数选择。
5. 把“total MC”“MC-LR”“同步估计”“未来预测”写进每个实验的机器可读元数据，禁止在报告标题中互换。

### P1：决定模型能否可信泛化

1. Erie 按年份外推，并在年份内按站点/采样事件分组；HABs 按调查周期或湖泊分组；EMLS 用重复的按国家/湖泊分组交叉验证，而不是 17 条单次测试。
2. 为同站同日、不同项目或重复分析建立 `sampling_event_id`，避免复制样本跨折。
3. 对每个特征记录“测量时间、结果返回时间、部署时是否可用”，据此分别建立 nowcast 与 forecast 特征表。
4. 用两阶段/障碍模型处理大量未检出：先预测是否超过 LOD 或管理阈值，再预测检出后的浓度。
5. 报告置信区间、按年份/站点/浓度区间的误差，以及高风险事件召回率，而不是只给整体 R²。

### P2：工程化与科学可复现性

1. 将重复脚本收敛到 `src/`：数据契约、特征管线、划分器、训练器、评估器各一份实现。
2. 加入单元测试：单位换算、`<LOD` 解析、全缺失求和、分组不重叠、未来特征截止时间。
3. 精确锁定 Python 与包版本；表格保存 Parquet；模型包同时保存预处理器、特征顺序、训练数据哈希和 Git commit。
4. 保存逐样本预测而不仅是汇总 JSON，以便复算任何指标和检查极端误差。
5. 用数据卡和模型卡记录适用区域、检测方法、禁用场景与已知偏差。

## 8. 生物学与检测概念入门

### 8.1 什么是微囊藻毒素和 MC-LR

微囊藻毒素是一大类环状七肽，已知同系物很多。它们可由微囊藻、浮丝藻等蓝藻中的某些产毒株产生；同一个蓝藻水华不一定产毒，也不一定以 MC-LR 为主。毒素常在完整细胞内，细胞破裂或衰亡时会释放到水中。

MC-LR 名称中的 L 和 R 指分子两个可变位置上的亮氨酸（Leucine）和精氨酸（Arginine）。它可抑制蛋白磷酸酶 PP1/PP2A，肝脏是重要靶器官。[MC-LR 与 PP1/PP2A 机制综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC2821003/)

WHO 2022 饮用水资料给出的**总微囊藻毒素**暂定终生指导值为 1 µg/L、短期指导值为 12 µg/L，指游离加细胞结合态总量；EPA 2015 的十日健康建议则是学龄前儿童/婴幼儿 0.3 µg/L、学龄儿童及成人 1.6 µg/L。两套数值的对象、持续时间和管理语境不同，不应混为同一个标签阈值。[WHO fact sheet](https://cdn.who.int/media/docs/default-source/wash-documents/water-safety-and-quality/chemical-fact-sheets-2022/microcystins-fact-sheet-2022.pdf?download=true&sfvrsn=e1b5c768_2)；[US EPA health advisory](https://www.epa.gov/sites/default/files/2017-06/documents/microcystins-report-2015.pdf)

在稀水溶液中，1 µg/L 数值上近似 1 ppb。它非常低，所以一个只在 mg/L 量级出现响应的工程菌线路，对实际预警可能没有用。

### 8.2 “浓度”取决于检测方法

- **LC-MS/MS**：按分子质量和碎片离子区分具体同系物，适合 MC-LR 定量，但只覆盖设定并有标准品的化合物。
- **ELISA**：抗体通常对共同结构有不同程度交叉反应，结果常更接近“MC-LR 当量”或某类总量，不等于精确的每种同系物之和。
- **PPIA**：利用微囊藻毒素抑制蛋白磷酸酶的活性，反映总体生物活性，但同样不特异于 MC-LR。
- **qPCR/mcy 基因**：表示潜在产毒生物或基因拷贝数。基因存在不代表当时已产生或释放多少毒素。

不同方法的数字不能在没有方法校准项的情况下直接拼在一个标签列里。[微囊藻毒素检测方法综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC7601875/)

还要分清：

- **细胞内/颗粒态**：毒素仍在蓝藻细胞内；
- **游离/溶解态**：毒素已释放到水中；
- **总量**：通常需要先裂解细胞，再测游离加细胞内。  

工程菌在水样中实际接触到哪一部分，取决于样品是否过滤、裂解和预处理；环境管理值与传感器读数必须对应同一操作定义。

### 8.3 检出限 LOD、定量限 LOQ 与 `<0.10`

- **LOD（limit of detection）**：能够与空白区分的最低水平；低于它不等于浓度严格为零。
- **LOQ（limit of quantification）**：能够以可接受精度定量的最低水平，通常高于 LOD。
- `<0.10` 的含义是“真实值在某个区间内、仪器不能可靠给出精确值”，在统计上叫**左删失**。

把所有 `<0.10` 转为 NaN 会丢掉“它很低”这一信息；一律替换为 0.05 则假装知道了并不存在的精确值。可用方法包括删失似然/Tobit、区间回归、多重插补敏感性分析，或先做“是否超过 LOD/管理阈值”的分类。

### 8.4 GFP 与 RFP 到底在响应什么

GFP（绿色荧光蛋白）和 RFP（红色荧光蛋白）本质上都是**报告蛋白**。它们把上游启动子的转录活动转换成可测光信号：

```text
MCLR → 识别分子/受体 → 信号转导 → 启动子开或关 → GFP/RFP 表达 → 荧光
```

关键点是：GFP/RFP 通常不直接结合或识别 MCLR。若没有明确的识别元件，换一种颜色不会让细胞获得特异性。已有研究在大肠杆菌 MG1655 暴露于 1 和 10 mg/L MC-LR 时，未观察到显著的转录组或代谢组响应；该浓度又比 1 µg/L 高 1000–10000 倍。因此，不应默认大肠杆菌的天然“压力启动子”能在环境相关浓度可靠感知 MCLR。[E. coli 暴露研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC5730168/)

一个双颜色设计可以有几种完全不同的含义：

1. **GFP 为响应信号，RFP 为组成型内参**：用绿色/红色比值抵消细胞数、照明和总体表达能力变化。这通常比只看单色强度稳健。
2. **两种颜色对应两个阈值或两条通路**：例如低风险绿、高风险红；这需要两套经过标定的传感线路，颜色本身没有风险含义。
3. **两种不同菌株分别发光**：这时比值还受两种菌的存活和比例影响，不能直接当作浓度。

典型 EGFP 的激发/发射峰约为 488/507 nm，mCherry 约为 587/610 nm；报告数据库给出的成熟时间约为 25 和 15 分钟，但实际数值会受菌株、温度和表达环境影响。[FPbase EGFP](https://www.fpbase.org/protein/egfp/)；[FPbase mCherry](https://www.fpbase.org/protein/mcherry/)

荧光不是“启动子一开就立刻出现”。蛋白需要转录、翻译、折叠和发色团成熟，常有数分钟到数十分钟延迟；稳定荧光蛋白还会形成记忆，使信号下降得很慢。[荧光蛋白成熟动力学](https://pmc.ncbi.nlm.nih.gov/articles/PMC8477756/)

实验和模型至少要记录：背景荧光、细胞密度/OD600、响应时间、温度、pH、溶氧、光漂白、光谱串色、传感器增益与批次。若用红色内参，可先做背景扣除和串色校正，再计算类似

\[
R(t)=\frac{F_{GFP}(t)-F_{GFP,blank}}{F_{RFP}(t)-F_{RFP,blank}}
\]

的比值；但分母接近零时会极不稳定，必须设置质量控制门槛。

### 8.5 剂量—响应曲线和 Hill 方程

最简单的饱和型响应可用 Hill 方程描述：

\[
F(x)=F_0+(F_{max}-F_0)\frac{x^n}{EC_{50}^n+x^n}
\]

- `x`：MCLR 浓度；
- `F0`：无 MCLR 时的漏表达/背景；
- `Fmax`：饱和响应；
- `EC50`：达到半最大响应的浓度，**不是 LOD**；
- `n`：曲线陡峭程度/表观协同性。

如果 MCLR 抑制某条通路，曲线可以是下降型。真实节点还需加入时间维度，例如用 mRNA、未成熟蛋白、成熟蛋白的常微分方程描述延迟和累积。实际浓度反演不只是“把 Hill 方程倒过来”，还要传播参数不确定度，并处理低于 LOD 和饱和区间；在饱和区，不同高浓度可能产生几乎相同荧光。

### 8.6 群体感应（quorum sensing, QS）

群体感应是细菌通过可扩散信号分子估计群体密度并协调基因表达的机制。经典 LuxI/LuxR 系统中：

- LuxI 合成 AHL 信号；
- AHL 随细胞增多而积累；
- AHL 与 LuxR 结合后激活目标启动子；
- 若又促进 LuxI，就形成正反馈放大。

[LuxI/LuxR 线路机制](https://pmc.ncbi.nlm.nih.gov/articles/PMC3261908/)；[LuxR-pLux-GFP 生物传感示例](https://pmc.ncbi.nlm.nih.gov/articles/PMC92623/)

QS 可以把弱输入放大并让群体同步发光，但它同时引入：

- **密度阈值**：相同 MCLR 在低 OD 与高 OD 下可能给出完全不同输出；
- **额外延迟**：必须先积累 AHL；
- **正反馈、滞后与双稳态**：输入下降后仍可能保持亮；
- **串扰与基质效应**：天然微生物、pH、温度、流动和 AHL 降解会改变信号；
- **代谢负担与进化稳定性**：长时间部署时高表达线路可能被选择掉。

所以 QS 不是免费的“灵敏度按钮”。校准实验必须做 `MCLR × 初始细胞密度 × 时间` 的矩阵，而不是只有一条终点剂量曲线。

## 9. 推荐的模型重构方案

### 9.1 数据层：先建立不可歧义的数据契约

每条记录至少包含：

```text
dataset_id, sampling_event_id, site_id, latitude, longitude,
sample_time, result_available_time, method, fraction,
target_name, target_value, unit, lod, loq, censored,
feature_value, feature_unit, qc_flag, source_version
```

所有单位在进入模型前由测试验证。原始值永不覆盖；清洗值、换算公式和删失标记另列保存。

### 9.2 环境模型分成三个明确任务

**任务 A：当前 total MC 同步估计**

- 允许使用同次蓝藻丰度、叶绿素、现场水质；
- 输出 total MC 分布和是否超过 0.3/1/1.6/12 µg/L 等不同语境阈值的概率；
- 明确命名 `nowcast` 或 `soft sensor`，不叫 forecast。

**任务 B：未来 1/3/7 天 total MC 预测**

- 只使用预测发出时已经可得的数据；
- 加入历史毒素、蓝藻和水质滞后/滚动特征、天气预报、风、流场、卫星遥感；
- 用 rolling-origin/forward chaining 评估，最后一个完整年份仅测试一次；
- 与“上一时刻浓度”“季节均值”等朴素基线比较。

**任务 C：MC-LR 探索与本地化**

- EMLS 用小模型、强正则和按国家/湖泊的重复分组 CV，重点报告不确定度；
- NCCA 作为左删失外部数据，使用区间/阈值评价；
- 新采东湖样本需同时测 MC-LR 与 total MC，记录方法、游离/总量和同系物谱；
- 在东湖数据足够前，只能做迁移风险评估或无监督协变量偏移，不声称已验证。

### 9.3 建模策略

推荐从可解释基线逐步增加复杂度：

1. Dummy/季节中位数；
2. 正则化线性或广义加性模型；
3. Random Forest、XGBoost/LightGBM；
4. 两阶段模型：`P(超过LOD或阈值)` × `检出后的浓度分布`；
5. 有足够连续时序后才考虑状态空间、时序树模型或深度网络。

主要评价指标应包括：

- 连续浓度：MAE、RMSE、对数尺度 MAE、Spearman、两倍误差内比例；
- 阈值风险：PR-AUC、灵敏度、特异度、阳性预测值、校准曲线；
- 高风险事件：事件召回率、提前量、漏报率；
- 概率输出：预测区间覆盖率和宽度；
- 所有指标给 bootstrap 或分组重采样置信区间。

R² 可以保留，但在分布偏移、样本很少或浓度范围很窄时会非常不稳定，不能作为唯一门槛。

### 9.4 生物传感模型

先独立建立最小可验证链路：

1. 明确 MCLR 的识别机制以及它对其他 MC 同系物、nodularin 和复杂水样组分的选择性；
2. 在认证标准品和机构安全规范下获得多浓度、多时间、多细胞密度的原始荧光曲线；
3. 设置培养基空白、无传感线路宿主、组成型荧光内参、无 MCLR 阴性、已知响应阳性、基质加标和交叉反应对照；
4. 同时记录 GFP、RFP、OD600、温度、pH、溶氧与仪器参数；
5. 用分层 Hill/动力学模型拟合不同生物批次，独立留出实验日验证；
6. 报告 LOD、LOQ、动态范围、响应/恢复时间、批间差、假阳性和储存稳定性。

不能用“训练集里曲线拟合得好”替代独立批次与真实水样验证。若识别元件在 µg/L 量级没有响应，后续 QS 或机器学习无法创造缺失的特异信息；它们最多放大已有信号，也会同时放大噪声。

## 10. 建议执行路线图

### 第 0 阶段：结果止损与清洗修复（1–2 周）

- 冻结现有 JSON 为“历史、不可用于最终结论”；
- 修复三项 P0 清洗错误，补单位/删失/求和测试；
- 生成每个数据集的数据卡和自动审计表；
- 重建 sampling event，检查重复、站点和时间戳；
- 不进行新模型调参，先确保数据正确。

**通过标准**：单位测试全部通过；随机抽取原始记录能追溯到清洗值；任何 `<LOD` 都保留界限；全缺失不再变成零。

### 第 1 阶段：可信 total MC 基线（2–4 周）

- 明确 Erie nowcast 与 forecast 两张特征表；
- 建立 train/validation/locked-test，测试年份只访问一次；
- 重跑 Dummy、Ridge/GAM、RF、XGBoost；
- 保存逐样本预测和分组置信区间；
- 做无强代理变量和严格结果可用时间的消融实验。

**通过标准**：验证集选择完成后锁定模型；最终测试优于朴素基线；高风险事件的召回率、误报率和置信区间达到预先写下的目标，而不只是 R² 变高。

### 第 2 阶段：工程菌与光学系统可行性（与第 1 阶段并行）

- 先证明上游识别元件在环境相关浓度范围内有可重复的输入—输出差异；
- 比较单色、双颜色内参与 QS 放大版本；
- 评估真实湖水基质、温度和藻细胞/溶解态处理的影响；
- 建立传感器反演模型和不确定度。

**通过标准**：独立实验日和加标真实水样中，关键管理浓度附近有可接受的检出能力；选择性、响应时间和批间变异有量化结果。

### 第 3 阶段：东湖本地数据与系统融合

- 按季节、站点、深度、藻华阶段进行配对采样；
- 同步获得 LC-MS/MS 或可靠参比方法、工程菌荧光、常规水质、天气/水动力与遥感；
- 先做本地校准和外部验证，再进行域适配；
- 地图输出同时显示预测均值、风险概率和不确定度/数据稀疏区。

**通过标准**：留出站点和未来月份上均通过；端到端误差分解能够区分生物传感误差、环境预测误差和空间插值误差。

- 实验日志和决策记录的形式。

**应停止使用或改名**

- 不再把 total MC 模型称为 MCLR 模型；
- 不再把同次采样关联模型称为未来预警模型；
- 不再引用受单位错误影响的跨域/合并成绩；
- 不再以固定测试集选特征、模型或 alpha；
- 不再用单次随机行划分作为主要证据；
- 不再把 `<LOD` 当缺失或精确零。

**必须补充**

- 工程菌识别元件与线路说明；
- GFP/RFP/OD/时间/环境条件的原始湿实验数据；
- 东湖本地参比毒素数据；
- 未来预测所需的连续时间数据和特征可用时间；
- 检测方法、样品组分（游离/总量）、LOD/LOQ 和 QA/QC 元数据；
- 独立锁定测试、模型卡和部署监测方案。

## 12. 最终评价

这个项目的科研问题有价值，现有工作也已经证明环境变量中存在可用于估计总微囊藻毒素的信号；但它目前更像一组探索实验，而不是一个经过验证的完整模型。最大问题不是算法不够复杂，而是**目标定义、单位、删失值、时间可用性和验证边界尚未稳定**。

最合理的下一步不是继续堆叠更多模型或追逐更高 R²，而是先修正数据契约和测试制度，把三条证据链分别做实：

1. 工程菌是否在目标浓度和真实水样中产生可校准、特异、及时的荧光；
2. 环境模型是否能在新年份/新站点提前预测，而不仅是解释同一水样；
3. 两者在东湖是否经本地参比方法验证，并能给出可信的不确定度。

做到这三点后，项目才能从“有吸引力的 iGEM 原型”走向“可以被复现、检验和逐步部署的蓝藻毒素监测系统”。
