# 水体藻毒素监测平台网页重设计规划

## 1. 项目理解与建设目标

本项目是 iGEM Dry Lab 的水体藻毒素智能监测与预警原型。完整闭环由“环境/节点数据采集 → 藻毒素风险预测 → 风险地图与告警 → 调度投放 → 实测反馈”组成，武汉东湖是当前演示区域。Web 平台不是宣传页，而是给团队成员、评审和后续利益相关方使用的可操作监控台。

当前仓库中：

- `model/` 与 `model_redo_v2/` 提供藻毒素浓度、区间及风险预测的建模依据；Web 端需要保留模型版本、置信区间、预测时段和高风险时间等字段。
- `hardware/` 描述 ESP32 检测节点和后续无人机投放链路；Web 端需要展示在线状态、电量、信号、位置、传感器读数和配对能力。
- `docs/plan.md` 明确后续会通过 MQTT、HTTP 与 WebSocket 接入数据中台、模型和任务调度；本轮前端使用 mock 数据，但必须用 service 层隔离数据来源。
- `design-assets/page-objectives-redesign/` 的四张设计稿定义本轮视觉与信息层级。

本轮目标：在保留 React 18 + Vite + TypeScript 技术路线的前提下，重构四个核心页面，使它们在 1536×960 桌面基准下接近设计稿，同时具备可演示的真实前端交互和清晰的后端接入边界。

## 2. 信息优先级

## 4. 统一视觉与布局

### 4.1 设计语言

- 主色：`#0878e8`；深色文字：`#14213d`；品牌深绿：`#064b43`。
- 背景：白色到 `#f1faff` 的浅水色渐变，辅以气泡和水波纹。
- 卡片：白色/半透明白、`#b9dcf5` 细描边、14–18px 圆角、非常轻的蓝色阴影。
- 状态色：正常绿、关注黄、警戒橙、高风险红、离线灰。
- 字体：中文系统无衬线字体；数据使用等宽数字特性，强调值加粗。
- 装饰素材只出现在空白区和边界，不遮挡图表、地图标记或按钮。

### 4.2 桌面基准布局

- 页面外框：视口四周 4px 间距，18px 圆角蓝色描边。
- 顶栏：约 104px；左侧品牌区域固定，右侧根据路由显示状态、筛选、搜索、通知和用户菜单。
- 侧栏：约 202px；四个导航项共享路由激活状态，底部放置气泡/吉祥物装饰。
- 主内容：16–20px 间距；允许在较小桌面端滚动，避免裁掉核心功能。
- 适配：主要保证 1280px 以上桌面；窄于 1280px 时压缩字号和间距，不隐藏业务信息。

## 5. 页面功能规划

### 5.1 总览 `/`

信息：在线/空闲/离线、平均与最高藻毒素、系统状态、告警摘要、趋势、最新采样。

交互：

- 趋势可切换近 7/14/30 天。
- 点击告警项进入带风险筛选参数的地图页。
- 最新采样支持 5 条/全部切换；设备行可进入对应地图点位。
- 顶栏刷新触发 mock 数据重新拉取并更新同步时间。

### 5.2 地图监视 `/map`

信息：东湖底图、设备标记、藻毒素热力图、风险图例、选中设备详情。

交互：

- 使用 Leaflet 实际地图，实现缩放、平移、定位回中心。
- 独立开关设备图层和热力图层。
- 点击标记更新右侧设备详情；搜索参数可定位设备。
- “查看历史数据”跳转数据分析页并携带设备 ID。
- 地图瓦片不可用时仍保留水色背景、热力层和标记，保证演示可用。

### 5.3 数据分析 `/data`

信息：藻毒素/水温/pH 多轴趋势、传感器对比、AI 预测与 95% 区间、模型置信度。

交互：

- 顶栏设备筛选和传感器筛选通过 URL 参数驱动图表。
- 预测时段支持 3/7/14 天切换。
- 导出当前筛选结果为 UTF-8 CSV。
- 图表 Tooltip 显示时间、单位、实测/预测状态和区间。

### 5.4 设备配对 `/device`

信息：设备卡片、读数、状态、扫描雷达、附近待配对设备。

交互：

- 使用 dnd-kit 拖拽排序，并同步到 service 层。
- 搜索名称/编号；状态筛选；刷新列表。
- 添加设备表单可创建 mock 设备；设备卡片支持编辑、删除与多选。
- 蓝牙/Wi-Fi 配对按钮展示连接中、成功/失败状态，并把成功设备加入列表。
- 扫描按钮触发可视化扫描状态，完成后更新发现列表。

## 6. 前端架构规划

```text
src/
  components/common/       通用按钮、弹层、提示、空态
  data/                    mock 数据和素材映射
  layouts/                 顶栏、侧栏、页面框架
  pages/                   四个路由页面
  services/
    apiClient.ts           HTTP 请求与统一错误
    monitoringService.ts   总览、读数、历史、预测
    deviceService.ts       CRUD、排序、扫描、配对
    realtimeService.ts     未来 WebSocket 连接入口
  types/domain.ts          领域类型和 API DTO
  styles/globals.css       Token、全局布局、Leaflet 样式
```

Service 默认返回 mock 数据并模拟网络延迟；设置 `VITE_USE_MOCKS=false` 后切换到 `VITE_API_BASE_URL` 指定的后端。组件不直接依赖 mock 文件，便于后续无痛替换。

## 7. 后端接入边界

本轮保留以下接口族，并在 `API_INTEGRATION.md` 给出完整请求/响应：

- `GET /api/v1/dashboard/summary`
- `GET /api/v1/readings/latest`
- `GET /api/v1/devices` / `POST /api/v1/devices`
- `PATCH /api/v1/devices/:id` / `DELETE /api/v1/devices/:id`
- `PUT /api/v1/devices/order`
- `GET /api/v1/devices/:id/history`
- `POST /api/v1/devices/scan` / `POST /api/v1/devices/pair`
- `POST /api/v1/predict`
- `GET /api/v1/analytics/trends`
- `WS /api/v1/realtime`

统一约定 ISO 8601 时间、浓度单位 `μg/L`、经纬度 WGS84、风险阈值 `<0.5 / 0.5–1.0 / 1.0–5.0 / >5.0`。

## 8. 验收清单

- 四个路由均可直接访问与刷新，无运行时错误。
- 1536×960 下布局、比例、颜色和信息层级接近四张设计稿。
- 地图缩放/平移/图层/点选有效；数据筛选和 CSV 导出有效。
- 设备搜索、添加、编辑/删除、配对模拟与拖拽排序有效。
- 所有页面通过 service 读取数据，接口切换配置清晰。
- `npm run build` 与 `npm run lint` 通过。
- 仅在本地 `feature/web-redo` 形成提交，不 push。
