# 蓝藻水华智能监测模型报告

生成日期：2026-06-01  
范围：`model/` 目录下的数据清洗、特征工程、模型训练、评估可视化与 SHAP 解释流程。

## 1. 总体结论

本模型模块围绕蓝藻水华和微囊藻毒素风险预测构建，当前主要支持三套可训练数据集：`habs_training`、`lake_erie` 和 `sf_estuary`。建模任务分为两类：

- **分类任务**：预测微囊藻毒素是否检出或是否超过阈值。
- **回归任务**：预测微囊藻毒素浓度，训练目标为 `log10(MICX)` 或对应数据集的 `log10(微囊藻毒素浓度)`。

从 `figures/` 当前结果看，**Lake Erie 数据集效果最好**，分类 ROC-AUC 为 0.9432，PR-AUC 为 0.9588，回归 R2 为 0.7422。原因是该数据集来自单一湖泊长期密集监测，且包含蓝藻叶绿素、总叶绿素、营养盐、水温等直接相关特征。`habs_training` 具备全国尺度泛化价值，但湖泊异质性和目标缺失率较高，回归效果有限。`sf_estuary` 样本量最小，结果只能作为探索性模型参考。

## 3. 数据清洗流程

清洗入口为：

```bash
cd model
python run_clean.py
```

整体流程如下：

```mermaid
flowchart LR
  A["原始 CSV 数据"] --> B["src/config.py 数据集路径配置"]
  B --> C["run_clean.py 调度各 clean()"]
  C --> D["src/datasets/*.py 专属清洗逻辑"]
  D --> E["src/clean.py 通用清洗工具"]
  E --> F["data/cleaned/*.parquet"]
  E --> G["data/cleaned/*_report.json"]
  G --> H["quality_report.json / v2_quality_report.json"]
```

通用清洗逻辑包括：

- 使用 `load_csv_safe()` 统一读取 CSV，设置编码、注释行、跳过行和 NA 标记。
- 使用 `replace_detection_limits()` 处理 `<0.15`、`bdl`、`nd` 等检测限表达。对 `<X` 可按半检测限 `X/2` 替换，或直接置为 NaN。
- 使用 `replace_sentinel_values()` 将 `-1000` 等哨兵值替换为 NaN。
- 使用 `fix_negative_values()` 将不合理负值替换为 NaN。
- 使用 `clip_outliers_iqr()` 对极端值打标，而不是直接删除。
- 使用 `generate_quality_report()` 记录行列数、缺失率和字段类型。
- 使用 `save_cleaned()` 输出 parquet 和 JSON 报告。

## 4. 建模流程详解

训练入口为：

```bash
cd model
python run_train.py --dataset habs_training --task both
python run_train.py --dataset lake_erie --task both
python run_train.py --dataset sf_estuary --task both
```

`run_train.py` 的命令行参数：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--dataset` | `habs_training` | 选择训练数据集，可选 `habs_training`、`lake_erie`、`sf_estuary`。 |
| `--task` | `both` | 选择 `classification`、`regression` 或同时运行。 |
| `--tune` | 关闭 | 预留 Optuna 调参开关，但当前训练主流程未实际调用调参逻辑。 |
| `--n-trials` | 50 | Optuna 搜索次数预留参数。 |
| `--seed` | 42 | 随机种子。 |
| `--cv` | 5 | 交叉验证折数。 |

### 4.1 数据集注册

`src/config.py` 中 `DATASET_REGISTRY` 定义了当前真正进入训练入口的数据集：

| 注册名 | 数据文件 | 分类目标 | 回归目标 | 时间列 | 分类阈值 |
|---|---|---|---|---|---|
| `habs_training` | `v2_habs_training_cleaned.parquet` | `MICX_DET` | `MICX` | `DATE_COL` | 已有 0/1 标签 |
| `lake_erie` | `v2_lake_erie_cleaned.parquet` | `Total Microcystins (µg/L)` | 同左 | `Date` | `> 0.15` |
| `sf_estuary` | `sf_estuary_cleaned.parquet` | `ucd.ppia.MC.total.ugL` | 同左 | `Collection_Date` | `> 0` |

### 4.2 特征工程

特征工程入口为 `build_feature_matrix_for(df, dataset, task)`。它会按数据集分派：

- `habs_training` 使用通用 `build_feature_matrix()`。
- `lake_erie` 使用 `_build_lake_erie()`。
- `sf_estuary` 使用 `_build_sf_estuary()`。

#### `habs_training` 特征

主要特征分组来自 `src/config.py`：

- 水质：温度、最大深度、分层、氨氮、表层溶解氧、DOC、总氮、总磷、浊度、硝态氮、pH、叶绿素 a。
- 气候：蒸发影响、水分盈亏、月均降水、月均温。
- 土地利用：农业、开发、森林比例。
- 地形/流域：fetch、基流指数、土壤可蚀性、径流、海拔、坡度等。
- 氮磷预算：氮盈余、总输入、化肥、畜禽废弃物、磷盈余、化肥磷、人类废弃磷等。
- 聚合输入：农业/开发来源的氮磷输入。
- 位置：经纬度。
- 类别：`AG_ECO3` 生态区 one-hot。
- 时间：从 `DATE_COL` 提取 `MONTH_sin`、`MONTH_cos`。

目标处理：

- 分类：使用 `MICX_DET`，删除目标缺失行，转为整数标签。
- 回归：使用 `MICX > 0` 的样本，目标取 `log10(MICX)`。

同时，代码会删除元数据列、目标列、高冗余氮磷预算列、共线性较强的列，例如 `KffactWs` 和 `wet_ws`。

#### `lake_erie` 特征

Lake Erie 专属特征更接近水华本身：

- 水深、透明度、水温。
- 总叶绿素、绿藻/蓝藻/硅藻/隐藻叶绿素。
- 硝酸盐、铵盐、亚硝酸盐、DRP、硅酸盐、总磷、TKN、总氮、TN:TP。
- 经纬度。
- 月份周期特征。

目标处理：

- 分类：`Total Microcystins (µg/L) > 0.15`。
- 回归：`Total Microcystins (µg/L) > 0` 后取 `log10()`。

#### `sf_estuary` 特征

SF Estuary 专属特征包括：

- 现场水温、DO、电导率、盐度、浊度、pH。
- NH4、NO3、Chloride、DOC、TOC、DON、SRP、TP、SiO2、VSS、TDS、TSS。
- 叶绿素 a、脱镁叶绿素。
- qPCR 总 MIC 指标。
- 经纬度和月份周期特征。

目标处理：

- 分类：`ucd.ppia.MC.total.ugL > 0`。
- 回归：正浓度样本取 `log10()`。

### 4.3 数据划分

`split_data()` 默认测试集比例为 20%：

- `habs_training` 如果存在 `DSGN_CYCLE`，会按 `DSGN_CYCLE × 目标` 联合分层。
- 分类任务按 y 分层。
- 回归任务按 y 的四分位分箱分层。

当前流程使用随机划分，不是严格按时间外推验证。因此，模型当前结果更适合说明“同分布测试集表现”，不能完全等同于未来年份预测能力。

### 4.4 模型训练

训练器位于 `src/train.py`，当前采用两类树模型：

- XGBoost：`XGBClassifier` / `XGBRegressor`
- LightGBM：`LGBMClassifier` / `LGBMRegressor`

二者都使用：

- 约 500 棵树，学习率 0.05。
- 最大深度约 5。
- subsample 和 colsample 控制采样。
- L1/L2 正则。
- early stopping。

当数据集小于 500 行时，自动使用更保守的小样本参数：

- 树数降为 300。
- 深度降为 3。
- 正则更强。
- LightGBM 的 `num_leaves` 降为 15。

集成方式为简单平均：

```text
ensemble_pred = mean([xgboost_pred, lightgbm_pred])
```

这种方式稳定、简单，但不会保证一定优于最强单模型；在小样本数据集上尤其可能被弱模型拉低。

### 4.5 评估流程

`evaluate_full_pipeline()` 会对每个模型分别评估，并在对应目录保存图像。

分类指标：

- ROC-AUC
- PR-AUC / Average Precision
- Accuracy
- Balanced Accuracy
- F1
- MCC
- Precision
- Recall
- 混淆矩阵
- ROC/PR 曲线

回归指标：

- RMSE(log)
- RMSE(原始浓度)
- MAE(原始浓度)
- R2
- Pearson r
- Spearman rho
- Within Factor-of-2
- 预测 vs 真实值散点图
- 残差分布图

### 4.6 SHAP 解释

`interpret_model()` 对保存后的第一个基学习器进行 SHAP 解释。当前脚本加载 `saved["models"][0]`，也就是 XGBoost 模型，而不是集成模型整体。

输出内容：

- `shap_bar.webp`：平均绝对 SHAP 重要性。
- `shap_beeswarm.webp`：全局 SHAP 分布。
- `dependence/`：Top 特征依赖图。
- `waterfall/`：高、中、低预测样本瀑布图。

## 6. 模型流程中的关键问题

### 6.1 数据层面

- `habs_training` 的 `MICX` 缺失率约 66%，导致回归样本远少于分类样本。
- `sf_estuary` 总样本只有 438 行，回归有效样本约 154 行，测试集很小。
- Lake Erie 的关键藻类特征较完整，且与目标机制更直接，因此效果明显更好。
- 当前原始数据目录未在工作区可见，复跑清洗依赖外部原始 CSV 是否存在。

### 6.2 建模层面

- 当前缺失值主要交由树模型原生处理，没有统一插补或缺失机制分析。
- 分类阈值固定使用 0.5 生成混淆矩阵，虽然 `find_optimal_threshold()` 存在，但主评估流程未使用优化阈值。
- `--tune` 和 `--n-trials` 参数存在，但主流程没有真正启用 Optuna 搜索。
- 集成模型是简单平均，不是 stacking 或加权集成。
- 交叉验证对回归任务使用分箱分层，但仍然是随机划分，不是时间外推或站点外推。
- SHAP 当前解释的是第一个基模型 XGBoost，不是完整 ensemble。
- 同一目录下分类/回归 SHAP 文件名相同，容易被后一次任务覆盖。

### 6.3 产物层面

- 当前工作区中没有发现 `model/models/` 目录，说明已训练模型文件未随当前仓库状态保留，或此前训练未保存/已被忽略。
- `figures/` 图像是当前最直接的运行结果证据，应视为报告解读的主要依据。

## 7. 改进建议

1. **补齐模型产物管理**：确认 `model/models/` 是否应纳入本地产物目录，至少保留模型版本、特征列和训练参数摘要。
2. **拆分 SHAP 输出目录**：建议改为 `figures/{dataset}/{task}/shap/`，避免分类和回归解释图互相覆盖。
3. **加入时间外推验证**：对 Lake Erie 和 SF Estuary 按年份切分，评估未来年份预测能力。
4. **加入站点外推验证**：对湖泊/站点做 group split，检验新地点泛化能力。
5. **显式使用阈值优化**：分类可同时报告固定 0.5 阈值和最大 F1 阈值。
6. **改进集成策略**：对 XGBoost 和 LightGBM 使用验证集加权，或训练轻量 stacking 模型。
7. **增强回归稳健性**：对高浓度样本单独评估，考虑分段模型、Huber/quantile 目标或不确定性区间。
8. **补充数据字典**：为关键字段提供中文说明，降低后续接入前端和报告展示成本。

## 8. 总结

当前 `model/` 已形成完整的蓝藻水华风险建模闭环：数据清洗、特征工程、XGBoost/LightGBM 训练、分类与回归评估、SHAP 可解释性分析均已实现。模型在 Lake Erie 单湖泊场景下表现强，适合作为项目展示中的高可信样例；在全国 HABs Training 数据上具备筛查能力，但回归精度受限；在 SF Estuary 上受样本量约束，主要作为方法可迁移性的探索案例。

对于 iGEM 蓝藻水华智能监测系统，当前模型最适合承担“风险预警排序”和“辅助解释”的角色：分类输出用于提示毒素检出风险，回归输出用于估计浓度量级，SHAP 输出用于解释触发风险的水质、营养盐和季节因子。
